## Story and outcome

As the platform, I want agents loaded from folders so adding an agent does not require a core edit.

## Files in scope

- `src/vme_core/registry.py`
- `tests/core/test_registry.py`

## Do not touch

- Deal Scout’s real package (VME-301). Tests build temporary agent folders.
- The runner process (VME-110)

## Acceptance criteria

- AC1: `Registry.discover(agents_dir, allowed_tiers, config_dir)` loads each `*/manifest.yaml`, skips folders whose name starts with `_`, imports `entrypoint` and `config_model` from that folder, and returns `LoadedAgent(manifest, agent_cls, config_model, path, config)`.
- AC2: A tier outside `allowed_tiers` is skipped with one log line. `public,private` does not load `sensitive`.
- AC3: An import error, a bad manifest, or an id that does not match the folder name is logged and skipped. Other folders still load.
- AC4: Two folders with the same manifest id raise. That is a fail-fast, not a skip. The process must not silently run one of them.

## Build steps

1. Import with `importlib.util.spec_from_file_location` under the package name `vme_agents.<id>`. Put the agent directory on that module’s path so `import models` inside the agent works. Prefer loading `agent.py` and `models.py` by file so the agent need not be an installed distribution.
2. Config: call `load_agent_config`. Missing config skips that agent (VME-103 AC3) after the manifest has loaded, with a clear log line.
3. Do not execute `run()` during discovery.

## Tests and done when

Temp directories: one good agent, one bad import, one wrong tier, one id/folder mismatch, one duplicate id. pytest, ruff, mypy green.

## Challenges and decision

Importing agent code at discovery executes module top-level code. Agents must keep side effects out of import time. The conformance suite (VME-502) is the later guard. This story’s good-agent fixture should be a few lines with no network.

Duplicate ids fail the whole discover call. A broken third agent still skips. Those are different on purpose: duplicates are ambiguous, a broken folder is isolated.

Windows vs POSIX path handling does not matter on the Ubuntu host. Tests should still use `pathlib`.
