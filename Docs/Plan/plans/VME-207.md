## Story and outcome

As the owner, I want Virtual Me to ask a simple question so an agent can request a choice without touching the outside world.

## Files in scope

- `src/vme_orchestrator/decisions.py`
- Routes `GET /v1/decisions` (admin) and `POST /v1/decisions/{id}/answer` (feedback or admin)
- `tests/orchestrator/test_decisions.py`

## Do not touch

- Any HTTP call to a merchant, bank, or broker
- Deal Scout, except that it may later set `payload.decision` and ignore `decision:*` (already noted in VME-309)

## Acceptance criteria

- AC1: A finding whose payload contains `decision = {question, options[≤3 of {id, label}], expires_in_minutes}` creates a `decisions` row. The push actions POST to `/v1/decisions/{id}/answer` with `{"option": "<id>"}` instead of the feedback URL. Still at most 3 actions.
- AC2: An answer is forwarded as `Feedback(action="decision:<option_id>")` with the finding snapshot.
- AC3: Unanswered rows past `expires_at` become `expired`, and the agent receives `decision:expired`.
- AC4: This module never performs an external action. The only side effect is a feedback post to the runner and a status update.

## Build steps

1. Validate option ids are short tokens (`^[a-z0-9_]+$`). Reject anything else with a dropped decision and a log line.
2. Expire on a schedule, at least every 5 minutes, in the orchestrator process.
3. Answering an expired or unknown decision is 409 or 404. Pick 404 for unknown and 409 for expired, and test both.

## Tests and done when

Create, answer, expire, and a test that the notifier payload contains no host other than `VME_PUBLIC_BASE_URL`. pytest, ruff, mypy green.

## Challenges and decision

Action buttons are the same ntfy mechanism as feedback, so the feedback token can also answer decisions (D19). That is intended. The answer body is an option id, not a URL and not a shell command.

Deal Scout v1 ignores `decision:*` (VME-309 AC4). This story can still ship without Deal Scout using it.

Do not add a generic “run this webhook” option. AC4 forbids it.
