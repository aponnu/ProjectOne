## Story and outcome

As Deal Scout, I want to fetch the configured feeds politely so one failure does not stop the others and no other host is contacted.

## Files in scope

- `agents/deals_slickdeals/sources.py`
- `agents/deals_slickdeals/tests/test_sources.py`

## Do not touch

- SQL migrations and `feed_status` persistence (D9, VME-304, VME-310)
- Parser (VME-303)

## Acceptance criteria

- AC1: `fetch_all(ctx, feeds) -> list[RawFeed]` fetches each enabled feed sequentially with `ctx.http.get(url, conditional_key=f"feed:{name}")`.
- AC2: `NotModified` becomes `RawFeed(name, not_modified=True)` and an empty body.
- AC3: A failed feed is a `RawFeed` (or sibling result) with `error` set. Later feeds still run. Nothing is written to SQLite in this story (D9).
- AC4: The only URLs passed to `ctx.http.get` are the enabled feeds’ URLs. The test’s fake client records calls and fails if any host is not `slickdeals.net`.

## Build steps

1. `RawFeed` is a pydantic model: `name`, `url`, `body: bytes | None`, `not_modified: bool`, `error: str | None`.
2. Disabled feeds are omitted, not errors.
3. Do not follow a feed URL that failed config validation. Trust `DealsConfig`.

## Tests and done when

respx or a fake `SafeHttpClient`: 200, 304, 503-then-success if the client retries internally, and a 503 that still returns `UpstreamUnavailable` to the fetcher as an error on that feed only. pytest, ruff, mypy green. No real Slickdeals calls.

## Challenges and decision

VME-105 already retries 429 and 5xx. The fetcher should not add a second retry loop. One exhausted feed becomes `error` and the next feed starts.

Conditional GET needs the store’s `ConditionalCache`. Tests inject a fake cache. Wiring the real `AgentStore` happens when `Agent.run` is assembled in VME-308. This story’s function takes `ctx`.

Master plan AC3 says the failure is recorded in `feed_status`. That table does not exist yet. D9 moves persistence to VME-310. The in-memory `error` field is the contract between them.
