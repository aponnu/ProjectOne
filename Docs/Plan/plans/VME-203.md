## Story and outcome

As the owner, I want a single notifier interface and an ntfy implementation so later stories can push and digest without talking HTTP themselves.

## Acceptance criteria

- AC1: `Notifier` protocol has `send_push(finding) -> DeliveryResult` and `send_digest(sections) -> DeliveryResult`.
- AC2: `NtfyNotifier` POSTs JSON to `NTFY_URL` with `Authorization: Bearer NTFY_TOKEN`. Body includes `topic`, `title`, `message`, `priority` (high 4, normal 3, low 2), `tags`, `click` (finding URL), and up to 3 `actions`. Each action is `http`, POST, URL `${VME_PUBLIC_BASE_URL}/v1/feedback/{finding_id}`, header `Authorization: Bearer ${VME_FEEDBACK_TOKEN}`, body `{"action":"<action>"}`, `clear: true`.
- AC3: Deal Scout push text follows Appendix D for a watch hit and an interest match. The formatter takes already-parsed fields (title, price, store, scores). It does not scrape.
- AC4: A digest body over 4000 bytes is split into `Digest 1/2` style parts. Each part is its own publish.
- AC5: A `sensitive` finding is sent as a generic title only (`Budget: 1 item needs attention` or the agent name plus “1 item needs attention”). Summary, URL, payload, and action buttons are omitted (rule R3).
- AC6: Each publish writes a `deliveries` row. Three failed attempts put the finding back to `queued_digest` when the caller asked for a push. The notifier returns the failure; the caller (router, VME-204) performs the status change if the finding row is not available here. This story must write the delivery row and return `ok=false` after 3 tries. Document the status handoff so VME-204 does not double-write.

## Build steps

1. Publish JSON, never the comma-separated `Actions` header (D19). Emoji labels and JSON bodies break that header.
2. Action labels come from `ActionSpec.label` and are already max 24 characters.
3. Tests use respx. No real ntfy.
4. Do not log the feedback token or the full Authorization header.

## Tests and done when

Exact JSON body for a watch-hit push. Digest split. Sensitive redaction. Delivery row on success and on a 500. pytest, ruff, mypy green.

## Challenges and decision

The feedback token is stored on the phone and in ntfy’s cache because it is inside the action (D19). The token must stay unable to do anything except feedback and decision posts (VME-201). Do not put the admin token in an action.

`VME_PUBLIC_BASE_URL` is the Tailscale URL of the orchestrator, including `http://` and port 8088. The phone must be on Tailscale or the button fails. That is intended. Document it in the module docstring for VME-404 to repeat in `docs/PHONE.md`.

Internal `httpx` in the orchestrator is the one exception to “agents use SafeHttpClient”. The ruff ignore is per file and must not spread. This client is not used for Slickdeals or any public host. If `NTFY_URL` is not on the Docker network or a Tailscale address, refuse to construct the notifier.
