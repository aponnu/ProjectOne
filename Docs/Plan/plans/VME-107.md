## Story and outcome

As an agent author, I want a private SQLite file and ordered SQL migrations so one agent cannot read another agent’s state.

## Files in scope

- `src/vme_core/store.py`
- `tests/core/test_store.py`

## Do not touch

- Deal Scout migration SQL (VME-304)
- Orchestrator SQLModel tables (VME-201)

## Acceptance criteria

- AC1: `AgentStore.open(data_dir, agent_id, migrations_dir)` creates `<data_dir>/agents/<agent_id>.db` in WAL mode and applies `NNNN_*.sql` in name order, once, tracked in `_migrations`.
- AC2: `kv_get`, `kv_set(key, value, ttl_seconds=None)`, `kv_delete`. Values are JSON. Expired keys return `None` and are treated as missing.
- AC3: `execute`, `fetchall`, and `fetchone` are async via `asyncio.to_thread` and accept parameters only. A SQL string containing a second statement is rejected.
- AC4: The store implements the `ConditionalCache` protocol from VME-105 (`ETag` / `Last-Modified` under the kv table).
- AC5: `agent_id` must match `^[a-z][a-z0-9_]*$`. `../x` and absolute paths are rejected. The database path is always `data_dir / "agents" / f"{agent_id}.db"`.

## Build steps

1. Create `_kv` and `_migrations` before agent migrations run.
2. Migrations run inside a transaction per file. A failure leaves that file unrecorded so the next open retries it.
3. TTL: store `expires_at`. `kv_get` deletes or ignores expired rows. Tests use a frozen clock injected into the store, not `sleep`.
4. Conditional cache keys are namespaced (`http-cond:`) so they do not collide with agent keys.

## Tests and done when

Idempotent migrate (open twice, one row in `_migrations`). TTL expiry. Path traversal rejected. A sample `0001_init.sql` and `0002_next.sql` in a temp dir apply in order. pytest, ruff, mypy green.

## Challenges and decision

`execute` that accepts arbitrary SQL is a footgun. The method exists because agents own their schema. It must still be parameterized. Reject anything that is not a single statement so a migration file is the only place multi-statement SQL is allowed, and migrations are read from disk by the migrator, not through `execute`.

sqlite3 on a gocryptfs mount is fine. Tests use `tmp_path`, not `/srv/vme`.

Foreign keys are off by default in sqlite3. The store should `PRAGMA foreign_keys=ON` so later agent SQL can rely on it.
