## Story and outcome

As an agent author, I want a small base class and a context object so an agent only contains its own logic.

## Files in scope

- `src/vme_core/agent.py`
- `src/vme_core/errors.py` (`FindingValidationError`)
- `tests/core/test_agent.py`

## Do not touch

- Registry import logic (VME-109)
- Runner scheduling (VME-110), except that the buffer API must be something the runner can drain: `drain() -> list[Finding]`

## Acceptance criteria

- AC1: `BaseAgent` and `AgentContext` match section 6.5: `setup`, abstract `run`, optional `on_feedback`, optional `health`. Context exposes `agent_id`, `tier`, `http`, `llm`, `store`, `log`, `profile`, `now`, `emit`.
- AC2: `ctx.emit(draft)` sets `agent_id` and `tier`, then checks `type` is in the manifest `finding_types`, the URL host is in `allow_link_domains` (or the URL is null), each action is in `feedback_actions`, and the payload is ≤ 8 KB of canonical JSON. A violation raises `FindingValidationError`. The exception message is safe to log (no profile secrets). The method does not swallow the error. The runner (VME-110) is what catches it and continues the run. Document that split so this story does not hide bugs.
- AC3: Successful emits append to a buffer. `drain()` returns them and clears the buffer.
- AC4: `ctx.profile` is a frozen pydantic model. Assigning to a field fails.

## Build steps

1. `AgentContextImpl` is constructed by the runner later. This story builds it in tests with fakes for http, llm, and store.
2. Link-domain check reuses the same host rule as VME-105 (lowercase, suffix match). A relative URL is invalid.
3. Payload byte size is `len(json.dumps(payload, sort_keys=True, default=str).encode())`.
4. `health` default returns `ok=True` and an empty message. The runner overlays last success. Do not read the orchestrator database here.

## Tests and done when

Emit cases: good finding, bad type, bad link host, bad action, oversized payload, frozen profile. pytest, ruff, mypy green.

## Challenges and decision

The master plan says validation failures are logged and the run continues. If `emit` swallows them, agents cannot tell a finding was dropped. Decision: `emit` raises `FindingValidationError`. VME-110 catches it, logs it, and continues. The story file for VME-110 repeats this.

`FindingDraft` has no tier. The context copies the manifest tier onto the finding. An agent must not be able to pass a different tier. There is no tier field on the draft.

Frozen profile: use `model_config = ConfigDict(frozen=True)` on the view model passed into the context, even if the loader’s model is mutable.
