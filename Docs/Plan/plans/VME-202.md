## Story and outcome

As Virtual Me, I want to accept findings from the runner once, store them, and hand the new ones to the router.

## Files in scope

- `src/vme_orchestrator/intake.py`
- Route mount in `src/vme_orchestrator/app.py`
- `tests/orchestrator/test_intake.py`

## Do not touch

- Router policy (VME-204). Call `router.route(finding)` if that function exists. If VME-204 has not landed, call a `route(finding)` protocol with a no-op default defined in `intake.py` that marks status `new`, and replace the no-op when VME-204 lands. Do not copy router rules into intake.

## Acceptance criteria

- AC1: `POST /v1/findings` (runner token) accepts at most 100 findings. Each item is validated as `Finding`. The response lists accepted and rejected ids. One bad item does not reject the batch.
- AC2: The finding tier must match the `agents` row for that `agent_id`. A mismatch is a per-item reject. Unknown `agent_id` is a per-item reject. Tests may insert the agent row directly.
- AC3: The same `(agent_id, dedup_key)` inside 7 days is stored with `status=dropped` and `drop_reason=duplicate`, and is not routed.
- AC4: Accepted findings are passed to `route()` before the response returns.
- AC5: `expires_at` in the past is stored as `dropped` / `expired` and is not routed.
- D13: If `finding.id` is already in the table, the item is `accepted` again and is not inserted or routed a second time (outbox retry).
- D12: Intake does not special-case price drops. The distinct key is the agent’s job. A test can show two findings with keys `abc` and `abc:19.99` are both routed.

## Build steps

1. Over 100 items: 422 for the whole request (the batch itself is invalid).
2. Dedup window uses `utcnow()` minus 7 days, compared to `created_at` of the earlier row. A dropped duplicate still counts as “seen” so a third post stays dropped.
3. Do not log payloads at info level. They can contain deal text. Log id, agent, type, and the reject reason.

## Tests and done when

Batch of mixed valid and invalid. Dedup inside and outside 7 days (frozen clock). Tier mismatch. Expired. Replay of the same id. pytest, ruff, mypy green.

## Challenges and decision

Storing duplicates as rows makes the 7-day query include them, which is what we want. It also means `findings` grows with retries of the same key. That is acceptable at Deal Scout volume. Do not add a second “unique” table in this story.

D12 exists because VME-304’s plain key would make a cheaper repost look like a duplicate. Intake stays dumb. If a price-drop finding arrives with the plain key, it will be dropped, and that is the agent’s bug.

`route()` inside the request means a slow ntfy call blocks intake. VME-203 retries inside the notifier with a short budget. If that proves too slow, a later story can queue. Do not build a queue here.
