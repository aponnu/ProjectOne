## Story and outcome

As the platform, I want one guarded HTTP client so an agent cannot call an unapproved host or send a request body.

## Files in scope

- `src/vme_core/http.py`
- `src/vme_core/errors.py` (create the network errors if the module is still a stub)
- `tests/core/test_http.py`

## Do not touch

- Agent fetch loops (VME-302)
- Squid config (VME-402). This client also enforces the allowlist in process, which is what makes HTTPS GET/HEAD real (Squid only sees CONNECT).

## Acceptance criteria

- AC1: With `allow_domains: [slickdeals.net]`, a mocked GET to that host or a subdomain succeeds. `https://example.com` raises `NetworkPolicyError` and is audited with `allowed=false`.
- AC2: There is no `post`, `put`, `patch`, or `delete`. `request()` accepts only `GET` and `HEAD`.
- AC3: A redirect to a non-allowlisted host raises `NetworkPolicyError` and is not followed.
- AC4: Requests to the same host are at least `min_seconds_between_requests` apart.
- AC5: If the injected `ConditionalCache` has an ETag or Last-Modified for the URL, the client sends `If-None-Match` or `If-Modified-Since`. A 304 returns `NotModified` and does not expose a body.
- AC6: 429 and 5xx retry up to 3 times with backoff 2, 4, 8 seconds, honoring `Retry-After` up to 300 seconds. After that, raise `UpstreamUnavailable`.
- AC7: Bodies over 5 MB raise `ResponseTooLarge` and the read stops.
- AC8: User-Agent comes from settings, default `VirtualMe/0.1 (personal RSS reader)`. Cookies are not persisted. Proxy comes from the environment (`HTTPS_PROXY`) via `trust_env=True`.

## Build steps

1. Wrap `httpx.AsyncClient(timeout=20, follow_redirects=False, trust_env=True)`. Follow at most 3 redirects manually. Check every `Location` against the allowlist before the next hop.
2. `get(url, *, conditional_key: str | None = None) -> HttpResponse | NotModified` and `head(url)`.
3. Host match: lowercase, IDNA, then `host == domain or host.endswith("." + domain)`. Reject URLs with a username, password, or non-http(s) scheme.
4. Per-host `asyncio.Lock` plus last-request timestamp for AC4.
5. `ConditionalCache` is a small protocol (`get_headers`, `put_headers`). VME-107 implements it. Tests use a dict fake.
6. Audit every attempt, including denials, through the VME-104 API. Hash the path. Log the host.

## Tests and done when

One respx test per AC. No real network. pytest, ruff, mypy green. `http.py` is the only new file allowed to import `httpx`.

## Challenges and decision

Retries plus the per-host gap can stack: a 429 with `Retry-After: 300` stalls a run. Cap a single wait at 300 seconds as specified, and let the runner timeout (VME-110) cancel the run. Do not add a second, quieter cap in this story.

Redirects to `http://` on an allowlisted host are still allowlisted. Deal Scout configs require `https` feed URLs (VME-301). The client allows both schemes so a redirect to HTTP is visible and tested, not silently upgraded. If the first URL is HTTPS and the redirect is HTTP, raise `NetworkPolicyError` (downgrade). That is stricter than the master plan and should be stated in the test name.

IDNA: `slickdeals.net` does not need punycode today. Still normalize so a later domain cannot bypass the suffix check with mixed case or a trailing dot.

Conditional GET needs a cache implementation. Shipping a memory cache inside the client would drop ETags every process restart. The protocol stays injected.
