## Story and outcome

As the owner, I want to reach the server from my phone and laptop without exposing ports to the internet.

## Files in scope

- `scripts/bootstrap_server.sh` (append Tailscale install; do not embed an auth key in the script)
- `docs/SERVER.md` (MagicDNS name, how `TAILSCALE_IP` is recorded, ACL note)
- `.env.example` only if the repo already has one; otherwise document the variable and let VME-101 create the example file

## Do not touch

- ntfy, Compose port bindings, UFW Part B (return to VME-001 after this story)
- A real `.env` in git

## Acceptance criteria

- From the phone on cellular, SSH to the Tailscale name works with the existing key. `tailscale up --ssh=false` so Tailscale’s own SSH server stays off. Host `sshd` over the tailscale interface is the access path.
- A scan of the LAN address shows no new listening ports from this story.
- The server’s Tailscale IPv4 is written to the server’s `.env` as `TAILSCALE_IP` (mode `600`, not committed). The example file lists the variable name with an empty value.

The master plan’s check against `http://<tailscale-name>:8090` is deferred to VME-404 (D4). Port 8090 does not exist yet.

## Build steps

1. Install Tailscale from Tailscale’s official repo.
2. `sudo tailscale up --ssh=false`. Complete login out of band. Enable MagicDNS.
3. Put the IPv4 from `tailscale ip -4` into the server `.env` as `TAILSCALE_IP`.
4. Optional: a Tailscale ACL so only the owner’s devices can reach TCP 8088 and 8090 later. Record whether it was applied.
5. From the phone on cellular, SSH in. Only then return to VME-001 Part B.
6. Script the install. Do not script an auth key. A second run should see an already-logged-in node and exit 0.

## Tests and done when

`docs/SERVER.md` records the MagicDNS name, the SSH-from-cellular result, and the LAN scan command and result. `TAILSCALE_IP` is on the server only.

## Challenges and decision

`--ssh=false` means a broken host `sshd` or a UFW rule that forgets `tailscale0` is a full lockout. Part B of VME-001 stays after this story, and a LAN SSH allow stays until the cellular SSH check passes.

Tailscale CGNAT addresses (`100.64.0.0/10`) are what VME-403 later allows as a destination from the edge subnet. This story only has to record the address.

MagicDNS names change if the tailnet rename happens. Compose and ntfy base URL should read from env, not a hardcoded name, when those stories land.
