## Story and outcome

As the owner, I want a morning and an evening digest so non-urgent items do not interrupt me.

## Files in scope

- `src/vme_orchestrator/digest.py`
- `POST /v1/digest/send-now` on the admin router
- `tests/orchestrator/test_digest.py`

## Do not touch

- The quiet-hours release job in the router (D14)
- Narrative prefix (VME-210). Leave a single hook `prefix: str = ""` that defaults empty.

## Acceptance criteria

- AC1: Digests run at `profile.notifications.digests` (default `07:30` and `19:30`) in the profile time zone.
- AC2: Select `queued_digest`, group by agent, sort by score descending, show the top 10 per agent, then a line `+N more: run vme findings list --agent <id>` when needed.
- AC3: Template matches Appendix D. No LLM call.
- AC4: An empty queue sends nothing and writes no delivery row.
- AC5: Included findings become `digested` with `delivered_at` set only after the notifier returns ok.
- AC6: `POST /v1/digest/send-now` with the admin token runs the same builder.

## Build steps

1. Scheduler timezone is the profile zone, not the container’s UTC default.
2. Rendering is a pure function `render(now, groups) -> str` so the snapshot test does not need the database.
3. Splitting over 4000 bytes stays in the notifier (VME-203). The builder may return one string.
4. A failed send leaves findings `queued_digest`.

## Tests and done when

Snapshot of a morning digest with two agents and an overflow line. Empty queue. `send-now` auth. pytest, ruff, mypy green.

## Challenges and decision

07:30 is after quiet hours end (07:00). Held urgent items flush at 07:00 (VME-204) and the digest follows at 07:30. Do not merge those into one message in this story. The owner can move the times in the profile later.

Digest text includes finding titles and slickdeals URLs. That is the point of the phone notification. Do not include payload blobs.

`vme findings` in Appendix D is not a command. The line must cite `vme findings list`, which VME-209 actually implements.
