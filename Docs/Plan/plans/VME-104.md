## Story and outcome

As the owner, I want a tamper-evident record of every AI call and outbound request so privacy can be checked later.

## Files in scope

- `src/vme_core/audit.py`
- `tests/core/test_audit.py`

## Do not touch

- Call sites in HTTP and LLM (those stories call this API)
- Orchestrator database

## Acceptance criteria

- AC1: `AuditLog.record_http(agent_id, method, host, path_hash, status, bytes, duration_ms, allowed, reason)` appends a row. The path is a hash, not the raw path (paths can carry query secrets later).
- AC2: `AuditLog.record_llm(agent_id, tier, provider, model, prompt_sha256, prompt_chars, output_chars, duration_ms, ok, error)` appends a row. Prompt text is stored only when `tier == public` and `VME_AUDIT_STORE_PUBLIC_PROMPTS=true`. Private and sensitive rows never store prompt text, even if the flag is on.
- AC3: Each row stores `prev_hash` and `row_hash = sha256(prev_hash + canonical_row_json)`. `verify()` returns false if any row was altered or deleted. The first row’s `prev_hash` is a fixed genesis constant.

## Build steps

1. sqlite3 in WAL mode at `<data_dir>/audit.db`. Serialize writes with one lock. Async methods use `asyncio.to_thread`.
2. Canonical JSON: sorted keys, no whitespace variance, so hashes are stable.
3. `verify()` walks the chain in `id` order and recomputes hashes.
4. No update or delete API. Tests that tamper must use a raw sqlite connection in the test, not a public method.

## Tests and done when

Write rows, flip one column with raw SQL, assert `verify()` is false. Assert a private-tier LLM row has null prompt text even when the flag is true. pytest, ruff, mypy green.

## Challenges and decision

Hashing `prev_hash + row_json` is ambiguous if the row includes its own hash. Exclude `row_hash` from the payload that is hashed, and include `prev_hash`. Document the exact byte string in the module docstring and lock it with a test vector. VME-405 depends on this staying stable.

WAL files (`-wal`, `-shm`) must sit next to the database on the encrypted volume. `lock.sh` cannot unmount while a connection is open. That is an operations note for VME-006, not more code here.

Two processes (runner and orchestrator) use two audit databases, per section 6.6. The constructor takes a path. Do not assume a single global file.
