## Story and outcome

As the owner, I want Virtual Me to decide what interrupts me so pushes stay rare and the rest waits for a digest.

## Acceptance criteria

Rules run in this order. `decide(finding, profile, now, counters) -> RouteDecision` is a pure function. The caller sends notifications and writes status.

- AC1: `urgency == high` and `score ≥ urgent_threshold` (default 0.80) pushes now, unless quiet hours or the push budget blocks it.
- AC2: Quiet hours default 22:00–07:00 in the profile time zone. High-urgency findings become `held`. They are not pushed during quiet hours unless `allow_urgent_in_quiet_hours` is true.
- AC3: Budgets default to 4 per hour and 12 per day (D11). Past either budget, status is `queued_digest`. The route log rule is `budget`. `drop_reason` stays empty (D16).
- AC4: Any other finding with `score ≥ digest_min_score` (default 0.55) is `queued_digest`. Below that, status is `dropped` and `drop_reason=low_score`.
- AC5: `type == system` (or agent id reserved for the watchdog) is pushed, still capped at 3 system pushes per day, and still obeys quiet hours unless `allow_urgent_in_quiet_hours` is true (D15).
- AC6: Every decision records the rule name that fired.
- D14: A scheduled job at the end of quiet hours loads `held` findings and sends them as one grouped notification, then marks them `pushed`. This job is not the digest job.

Push failure after 3 tries (VME-203) sets the finding back to `queued_digest`.

## Build steps

1. Quiet-hour comparison uses `zoneinfo` and the profile zone. Cover 21:59, 22:00, 06:59, 07:00, including a DST date in America/Chicago.
2. Counters count successful pushes in the rolling hour and the local calendar day, plus system pushes today.
3. The quiet-hours release job uses the orchestrator scheduler and the profile zone. If quiet hours are disabled (start == end), do not schedule it.
4. Grouped release uses `send_digest` or a single push with a short list. It must not re-run the score rules and drop them.

## Tests and done when

Table-driven tests, at least one case per rule, plus the four boundary times. One test that a budget overflow does not set `drop_reason`. One test that held findings flush at 07:00. pytest, ruff, mypy green.

## Challenges and decision

The success metric “≤ 6 pushes a day” is not the code default (D11). Do not “fix” the default to 6 in this story.

`drop_reason=budget` in the master plan contradicts status `queued_digest`. D16 wins.

System findings “always pushed” conflict with the cap and with quiet hours. D15 picks a single behavior so the watchdog cannot buzz the phone overnight.

The release job can double-send if the process restarts mid-send. Mark `pushed` only after a successful delivery row. A crash retry may send twice. Accept that for v1 and keep the delivery row as the audit.
