## Story and outcome

As the owner, I want an optional short morning summary from the local model, in front of the normal digest.

## Files in scope

- `src/vme_orchestrator/digest.py` (the prefix hook from VME-205)
- A small helper module `src/vme_orchestrator/narrative.py` if `digest.py` would otherwise cross ~300 lines
- `tests/orchestrator/test_narrative.py`

## Do not touch

- Evening digest (no narrative unless the profile later gains a flag; v1 is morning only)
- Deal Scout judge prompts

## Acceptance criteria

- With `profile.notifications.narrative_brief: true`, the morning digest is prefixed with at most 3 sentences from `LLMGateway`.
- The gateway is bound as tier `private`, so cloud is refused.
- Input is only the digest’s titles and scores. No payload, no URLs, no profile secrets beyond what is already in those titles.
- If the LLM raises `LLMUnavailable`, `LLMOutputError`, or times out, the digest is sent without the prefix.
- With the flag false, the gateway is not called.

## Build steps

1. The orchestrator needs `OLLAMA_URL` and the gateway. Construct it in the digest job, not at import time.
2. Schema: `{ "text": str }` with a max length. Reject the prefix if it contains `http://` or `https://`.
3. Audit the call like any other private LLM call (hash only).

## Tests and done when

Fake gateway returns three sentences. Fake gateway raises, digest still renders. Flag off, zero calls. pytest, ruff, mypy green.

## Challenges and decision

The orchestrator container is 512 MB and has no GPU. It only sends a small prompt to Ollama on the `core` network. Do not load a model inside the orchestrator process.

Titles can contain store names the owner searched for. That text stays on the local machine (private tier). Do not include watchlist keyword lists from the agent config. Titles and scores only.

This is Could-priority. If the gateway is awkward to construct from the orchestrator, ship the flag-off path and a tested helper, and do not block S4.
