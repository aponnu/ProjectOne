## Story and outcome

As the developer, I want a reproducible repo with quality gates so that every later story lands clean.

## Files in scope

Create the section 8 tree as empty modules with docstrings, plus tooling:

- `pyproject.toml`, `uv.lock`
- `README.md` (how to run pytest, ruff, mypy; no personal data)
- `.env.example` (variable names only, from VME-103’s list, empty values)
- `.gitignore`
- `.pre-commit-config.yaml`
- `.cursor/rules/vme.mdc` (Appendix F of the master plan)
- `src/vme_core/` modules listed in section 8, each a short module docstring and `__init__.py`
- `src/vme_orchestrator/` the same, including `notifier/`
- `agents/.gitkeep` (no Deal Scout yet)
- `config/.gitkeep`
- `tests/core/.gitkeep`, `tests/orchestrator/.gitkeep`, `tests/integration/.gitkeep`, `tests/conformance/.gitkeep`
- `docs/.gitkeep` if needed so later stories have a home. Do not move or rewrite `Docs/Plan/VIRTUAL_ME_BUILD_PLAN.md`

Package layout must match the console scripts below. If the repo uses a `src/` layout, set the hatch/uv package config so `vme_core` and `vme_orchestrator` import.

## Do not touch

- Business logic inside the empty modules
- `scripts/bootstrap_server.sh` and the S0 scripts, except a one-line pointer from the README if those scripts already exist

## Acceptance criteria

- AC1: `uv sync` creates the environment. `uv run pytest` runs and exits 0 with zero tests collected, or with a single skipped placeholder. It must not error.
- AC2: `uv run ruff check` and `uv run mypy src agents` pass. `agents/` may be empty; mypy must still be configured so a missing tree is not a failure (`agents` package path optional until VME-301).
- AC3: A temporary import of `httpx` outside `src/vme_core/http.py` fails ruff. Prove this with a fixture test or a documented negative check that is not left failing in the tree. The committed tree stays clean.
- AC4: `.pre-commit-config.yaml` runs ruff, mypy, and gitleaks.

## Build steps

1. Python 3.12, uv. Dependencies from master plan section 7.1, pinned via `uv.lock`. Dev: pytest, pytest-asyncio, pytest-cov, respx, mypy, ruff, pre-commit.
2. Console scripts: `vme = vme_orchestrator.cli:app`, `vme-orchestrator = vme_orchestrator.app:main`, `vme-runner = vme_core.runner:main`. Those functions can be stubs that raise `SystemExit` with “not implemented” until their stories. Importing them must succeed.
3. Ruff select: `E`, `F`, `I`, `B`, `UP`, `ASYNC`, `S`, `TID`, `RUF`. Ban `httpx`, `requests`, `aiohttp`, `urllib.request`, and `ollama` via `flake8-tidy-imports`. Per-file ignores: `src/vme_core/http.py` may import `httpx`; `src/vme_core/llm.py` may import `httpx` only.
4. mypy strict for `src/` and `agents/`.
5. `.gitignore`: `.env`, `data/`, `config/**/*.yaml`, with `!config/**/*.example.yaml`.
6. Copy Appendix F into `.cursor/rules/vme.mdc`. Point the “read the plan” line at `Docs/Plan/VIRTUAL_ME_BUILD_PLAN.md` and `Docs/Plan/plans/`, because this repo does not use `docs/BUILD_PLAN.md`.
7. Coverage config may be declared now (90% `vme_core`, 80% agents) but the fail-under gate stays off until those packages have real code. Do not fail VME-101 on coverage of docstrings.

## Tests and done when

A fresh `uv sync` on a clean venv passes AC1–AC4. `gitleaks` is configured even if it has nothing to scan yet.

## Challenges and decision

The master plan says save the plan as `docs/BUILD_PLAN.md`. This repo already uses `Docs/Plan/VIRTUAL_ME_BUILD_PLAN.md`. On Linux the server is case-sensitive. The cursor rule must cite the real path.

Empty modules and `mypy --strict` conflict if stubs are untyped. Give stub functions explicit return types (`None`) and a short docstring.

Banned-API checks fail the build if a story later imports `httpx` in the orchestrator. VME-203 adds a commented per-file exemption for `notifier/ntfy.py` only. Do not add that exemption in this story; leave the ban global so the later story has to justify it.
