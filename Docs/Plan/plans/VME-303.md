## Story and outcome

As Deal Scout, I want structured deals from messy RSS so matching does not depend on HTML scraping.

## Acceptance criteria

- AC1: `parse(raw: RawFeed) -> list[Deal]` uses feedparser. `Deal` fields: `guid`, `title`, `link` (host must be `slickdeals.net`, otherwise skip the item), `published_at`, `feed_name`, `price: Decimal | None`, `list_price: Decimal | None`, `store`, `store_domain`, `thumb_score: int | None`, `description_text` (plain text, max 1000 chars), `is_frontpage` (`feed_name == "frontpage"`), `normalized_title`.
- AC2: Price is a `Decimal`. "free" or "$0" is `0`. Multiple prices in a title are tested, not guessed silently: record the chosen rule next to the regex.
- AC3: Thumb score from `Thumb Score:\s*([+-]?\d+)` in the description text.
- AC4: Store from the description. The master-plan regex is the starting point and must be updated so a fixture line like `Walmart [walmart.com] has` and `*Walmart [walmart.com] *has` both match (D20).
- AC5: `normalized_title` is lowercase, with prices, punctuation, and “free shipping” / “free s&h” phrases removed, whitespace collapsed.
- AC6: Only `guid`, `title`, and `link` are required. One bad item does not fail the feed.
- D20: Two-digit years in `pubDate` (`12 Apr 26`) become 2026, not year 26 or 1926. `published_at` is timezone-aware UTC.

## Build steps

1. Capture fixtures with `curl` from the server or a developer machine. Strip nothing personal because the feed is public, but do not add profile YAML beside the fixture. Commit a trimmed fixture (a handful of items), not an unbounded snapshot, if the file would be huge. Keep at least one item with a store, a thumb score, two prices, and a two-digit year.
2. Description HTML is stripped with selectolax (or feedparser’s summary) to plain text before regexes run.
3. Comments above the regexes cite the fixture line they were adjusted for.

## Tests and done when

Fixture tests plus: no price, HTML entities, missing description, off-domain link skipped, two-digit year, asterisks around the store. pytest, ruff, mypy green.

## Challenges and decision

The live frontpage feed has been observed with `pubDate` like `Sun, 12 Apr 26 17:24:19 +0000` and descriptions like `*Walmart [walmart.com] *has`. The master-plan store regex does not allow the asterisks. D20 says the fixture wins over the original regex. Do not “fix” year 26 by dropping `published_at`. VME-310’s staleness check needs a real timestamp.

Titles such as `Naruto $8.40, SpongeBob $8.20` contain two prices. Prefer the price nearest a store sentence in the description when it exists; otherwise the first title price. Lock that rule with tests so VME-304’s 5% drop compares the same field every run.

`list_price` has no reliable source in the master plan. Leave it `None` unless the fixture shows a consistent “was $X” pattern. Do not invent a second regex without a fixture line.

feedparser is not banned. It does not open the network if you pass the body bytes.
