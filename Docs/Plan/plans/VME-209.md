## Story and outcome

As the owner, I want a CLI on my laptop that operates Virtual Me over Tailscale with the admin token.

## Files in scope

- `src/vme_orchestrator/cli.py`
- `tests/orchestrator/test_cli.py`

## Do not touch

- Server-side route behavior, except to add a thin read endpoint if a command has no API yet. Prefer existing routes from section 6.7.

## Acceptance criteria

These commands use `VME_ADMIN_TOKEN` and `VME_ORCHESTRATOR_URL`. Output is a rich table or a single line. Exit code is non-zero on HTTP errors.

- `vme status`
- `vme agents list`
- `vme agents run <id>`
- `vme agents enable <id>`
- `vme agents disable <id>`
- `vme findings list` with `--agent`, `--status`, `--since` (default `24h`), `--limit` (default 50)
- `vme digest send-now`
- `vme profile validate` (calls VME-103’s validator; D7). This subcommand reads a local path and does not need the API.
- `vme stats <agent_id>` prints `not implemented until VME-312` and exits 2 (D8).
- `vme new-agent` prints `not implemented until VME-501` and exits 2 (D8).

## Build steps

1. Typer app. The console script already points at `cli:app` from VME-101.
2. Tests use Typer’s `CliRunner` and a mocked HTTP layer (respx or a fake client). No live server.
3. `status` shows, per agent, last run, last success, failures, findings in the last 24 hours, open decisions, and the last delivery. Add a `GET /v1/status` admin route in the orchestrator if the existing routes cannot supply that in one call. That route is in scope because the CLI cannot invent the numbers locally.
4. Do not print tokens. Do not read `.env` from the encrypted server path inside tests.

## Tests and done when

One invocation per command against mocks, including both stubs. pytest, ruff, mypy green.

## Challenges and decision

The master plan lists `vme stats` and `vme new-agent` as acceptance criteria of this story. Those features are VME-312 and VME-501. D8 keeps this story shippable in S3. When those stories land, they replace the stubs in `cli.py`. That edit is in their file lists.

`profile validate` must work on the laptop against a copy of the example file, without a Tailscale session.

Rich tables need a width. Tests should set `COLUMNS` or use rich’s test console so they do not flake.
