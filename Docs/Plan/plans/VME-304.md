## Story and outcome

As the owner, I want each deal once, and a separate alert when the same deal is actually cheaper.

## Files in scope

- `agents/deals_slickdeals/migrations/0001_init.sql`
- `agents/deals_slickdeals/dedup.py`
- `agents/deals_slickdeals/tests/test_dedup.py`

## Do not touch

- Scoring and `ctx.emit` (VME-308)
- Orchestrator dedup window (VME-202). This story must produce keys that survive that window (D12).

## Acceptance criteria

- AC1: `0001_init.sql` creates `seen_deals(guid PK, dedup_key, price, first_seen_at, last_seen_at, emitted)`, `price_history(watch_item_id, price, deal_guid, seen_at)`, `feed_status(feed_name PK, last_ok_at, last_new_item_at, last_error, consecutive_failures)`, `feedback_examples(id, kind, text, embedding_json, created_at)`.
- AC2: Base key = `sha256(normalized_title + "|" + (store_domain or ""))` hex, first 32 chars.
- AC3: A deal is new if the guid is unseen and the base key is unseen in 14 days. It is a price drop if the base key was seen with a price at least `price_drop_pct` (default 5) higher. The finding key for a price drop is `base_key + ":" + price` (D12). The finding key for a new deal or a same-price repost is the base key. Same-price reposts are not “new”.
- AC4: `seen_deals` rows with `last_seen_at` older than 30 days are deleted at the end of a run.
- AC5: `record_price(watch_item_id, price, deal_guid, seen_at)` appends `price_history`. `lowest_price(watch_item_id, days=90) -> Decimal | None` returns the min in that window.

## Build steps

1. Apply the migration through `AgentStore.open` in tests.
2. Price comparisons use `Decimal`, not floats.
3. A missing price cannot be a price drop. It can still be new.
4. Persist `feed_status` only as an empty table in this story (D9). VME-310 writes the rows. The fetcher does not have to be changed here.

## Tests and done when

New deal, repeat, same-price repost, 10% cheaper repost (different finding key), missing price, purge at 30 days, `lowest_price`. pytest, ruff, mypy green.

## Challenges and decision

Without D12, the orchestrator stores the cheaper deal as `duplicate` for 7 days and the owner never hears about it. The base key still dedups the agent’s own “is this new?” check. Only the emitted finding key changes for a drop.

`sha256(...)[:32]` is hex characters, not raw bytes. Tests should lock the encoding (`utf-8` title and domain).

`price_history` grows for every watch-item match, including ones that are not emitted. VME-305 decides what a match is. This story only provides the helper. Do not call it from the parser.

Purge of `seen_deals` at 30 days while “seen in 14 days” defines newness means a deal can reappear after 14 days even if the row is still there, and the row itself dies at 30. Implement the predicates exactly that way. Do not “simplify” them into one number.
